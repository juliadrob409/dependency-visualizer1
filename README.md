# Dependency Visualizer

## Общее описание

Dependency Visualizer — консольное приложение для получения и
визуализации графа зависимостей пакетов Maven. Проект выполняется
поэтапно. На первом этапе реализована загрузка и проверка настроек
из XML-файла.

## Настройки

Настройки находятся в файле `config.xml`.

| Параметр | Описание | Пример |
|---|---|---|
| `package` | Координаты Maven: groupId:artifactId | `junit:junit` |
| `repository` | URL Maven-репозитория или путь к тестовому файлу | `https://repo.maven.apache.org/maven2` |
| `test_mode` | Режим тестового репозитория: true или false | `false` |
| `version` | Версия пакета | `4.13.2` |

При `test_mode=true` путь к тестовому файлу указывается относительно
расположения `config.xml` либо как абсолютный путь.

## Структура проекта

- `src/` — исходный код приложения.
- `tests/` — автоматические тесты.
- `config.xml` — пользовательские настройки.
- `test_repository.txt` — пример файла тестового репозитория.
- `run.bat` — скрипт запуска в Windows.

## Запуск


Запуск из корневой папки проекта:

```bash
python -m src.main
```

Можно передать путь к другому XML-файлу:

```bash
python -m src.main path/to/config.xml
```

## Запуск тестов

Из корневой папки проекта:

```bash
python -m unittest discover -s tests -v
```




## Описание этапов

Этап 1. Работа с конфигурацией

Реализовано чтение настроек из XML-файла, проверка корректности параметров и вывод конфигурации в формате ключ-значение.

Этап 2. Получение прямых зависимостей

Программа получает POM-файл Maven-пакета из указанного репозитория с помощью HTTP-запроса.

Из XML-файла извлекаются прямые зависимости: groupId, artifactId, version и scope.

Этап 3. Построение графа зависимостей

Реализовано построение полного графа зависимостей с использованием итеративного алгоритма поиска в глубину (DFS).

Программа обрабатывает как Maven-зависимости, так и тестовый граф из текстового файла.

Для построения тестового графа используется следующий формат:

A: B, C
B: D
C: D, E
D:
E: F
F:

Каждая строка содержит имя пакета и список его зависимостей. Если зависимостей нет, после двоеточия оставляется пустое место.

При построении графа учитываются уже посещённые пакеты, что позволяет избежать повторной обработки узлов и бесконечного обхода при наличии циклических зависимостей.

Пример использования

При корректной конфигурации программа выводит параметры:

```text
Параметры конфигурации:
Имя пакета: A
Репозиторий: test_repository.txt
Тестовый режим: True
Версия: 1.0

Граф зависимостей:
A:
  - B
  - C
B:
  - D
D:
  - F
F:
  Зависимости отсутствуют.
C:
  - D
  - E
E:
  - F
```
Этап 4. Определение порядка загрузки зависимостей

На данном этапе реализовано определение порядка загрузки пакетов с учётом их зависимостей.

Для определения порядка используется обход графа в глубину. Пакет добавляется в результат после обработки всех его зависимостей. Благодаря этому зависимости всегда располагаются раньше пакетов, которые от них зависят.

Также реализована проверка графа на наличие циклических зависимостей. При обнаружении цикла программа выводит сообщение об ошибке.

Для вывода порядка загрузки используется дополнительный параметр командной строки --order.

Запуск:

python -m src.main --order

Пример результата:

Порядок загрузки зависимостей:
- F
- D
- B
- E
- C
- A

Без параметра --order программа по-прежнему выводит граф зависимостей.

Для проверки реализованы тесты определения порядка загрузки, обработки общих зависимостей и обнаружения циклов.
